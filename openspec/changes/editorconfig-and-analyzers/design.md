## Context

This change ports the proven quality baseline from the reference project
(openlearning) and adapts project names. Two files carry almost all the
weight:

1. **`.editorconfig`** — copied wholesale with project-specific subtree rules:
   `src/OpenDockify.Data/Migrations/*.cs` (CA1861 off, regenerated by
   `dotnet ef`) and `tests/**/*.cs` (CA1707 off, underscore test names).
   Everything else stays error-level: naming, ordering, style, formatting.

2. **`Directory.Build.props`** — copied with `TreatWarningsAsErrors=true`,
   `Nullable=enable`, `AnalysisLevel=latest-recommended`,
   `EnforceCodeStyleInBuild=true`, `Deterministic=true`. It also carries the
   NuGet audit block (nuget-audit change) and the Husky restore target
   (git-hooks change); those are added by their own changes, but the props
   file is the shared home.

`SonarAnalyzer.CSharp` is a solution-wide `PackageReference` with
`PrivateAssets=all` so violations surface as build errors but the analyzer
never leaks into consumers.

## Goals / Non-Goals

**Goals:**
- Deterministic, error-level style + analyzer enforcement.
- One shared props file; zero per-project drift.
- Scoped relaxations only for regenerated/generated or test-convention code.

**Non-Goals:**
- Adding a custom formatter or lint pipeline beyond the SDK's `dotnet format`.
- Relaxing style for handwritten production code.

## Decisions

- **Copy `.editorconfig` and `Directory.Build.props` from the reference repo
  and adapt names** — the rules are battle-tested; consistency with the
  established pattern reduces review burden.
- **Warnings are errors** (`TreatWarningsAsErrors`) so CI and local builds
  agree; `WarningsNotAsErrors` allowlist stays empty (each entry needs
  justification).
- **Format gate is `dotnet format --verify-no-changes`** in CI; a pre-commit
  hook gives fast local feedback (git-hooks change).

## Risks / Trade-offs

- [Risk: aggressive analyzers slow onboarding] → Mitigation: the rules match
  the reference project already in use; violations are actionable messages,
  and scoped suppressions exist for generated/test code.
- [Risk: analyzer package version drift] → Mitigation: pin the exact version
  (e.g. `10.32.0.713`), verify the build gate after any upgrade.

## Migration Plan

1. Copy `.editorconfig` and `Directory.Build.props` from the reference repo,
   renaming OpenLearning→OpenDockify paths and the solution name.
2. Update subtree rules to `src/OpenDockify.Data/Migrations/*.cs`.
3. Add `SonarAnalyzer.CSharp` reference to `Directory.Build.props`.
4. Verify: `dotnet format --verify-no-changes` clean; `dotnet build` 0/0.
